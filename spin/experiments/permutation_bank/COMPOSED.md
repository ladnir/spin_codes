# Composed routing banks: speed and heuristic tradeoffs

The [final result](TARGET_RESULT.md) meets the median timing target with the
rotated row-map heuristic, after exact screening and further optimization.
The original-family fixed-code path and public library remain unchanged.
This document records the earlier cyclic-row candidate and bank construction.

Update: [exact tail screening](QUALITY.md) found complete row-support alignment
with probability 2^-16 in the fast cyclic-row family. A richer prototype
improves that tested tail; its final optimized version meets the target. Neither
candidate is promoted to a public default. The same report establishes the
one-active-row routing marginal under the specified independent setup model.

## Why a different bank helps

The earlier small bank computes two composed permutations for every address.
`Composed.h` instead stores the resulting destination coordinates directly.
The encoder prepares only one region's 8 KiB address buffer at a time.
No full route is generated for a fresh code.

The fastest variant uses cyclic position shifts within each region. Two
contiguous copies can prepare the shifted address buffer. Independent fresh
column shifts within outer rows add more diversity, at an additional cost.
The optimized implementation fuses those shifts into the copy using SIMD.
It checks region boundaries outside the unrolled inner emitter and indexes
each epoch through its own 128-entry address window.

One additional optimization does not change the sampled maps at all.
`Masks.h` vectorizes SplitMix and the IMT mask correction. It preserves every
mask generated by the previous implementation for the same seed. If a vector
batch encounters a rejected zero mask, it falls back to the previous generator.
Exact comparisons passed for 2,048 seeds, including 15 rejection fallbacks.

## Family and sampling

There are 2,048 outer rows of 256 coordinates and 256 inner regions of
2,048 positions. Let C be the number of tables stored per region.

At bank creation, sample independent row permutations R_r on 256 coordinates.
For every stored region h, sample C independent permutations P_{h,j} of the
2,048 row labels. Precompute the inverse routing tables

```
T[h,j,p] = (r, inverse(R_r)[h]), where r = P[h,j,p].
```

Each fresh code samples a uniform permutation sigma of the 256 regions.
Independently for each actual region g, sample a table index j_g and a
position shift b_g modulo 2,048. Independently for each outer row r,
sample a column shift d_r modulo 256. The inverse route is

```
(r,c) = T[sigma(g), j_g, (p + b_g) mod 2048]
Phi(g,p) = (r, (c + d_r) mod 256).
```

The code also samples fresh IMT masks. For C=1, table selection is trivial;
the bank still contains 256 independently sampled region permutations.
The implementation retains unused XOR/rotation draws from earlier variants
for seed compatibility; those unused values do not add family diversity.

Every map is bijective. Each outer row still contributes exactly one bit
to each actual region. The row shifts, region shifts, and shared region
permutation are bijective relabelings of the precomputed route.
None of this establishes distance or a PCG security bound.

The code owns its parameters and masks but borrows the bank. Keep the bank
alive and do not move or mutate it while a code refers to it. Scratch must
also be private to each concurrent encode.

## A rejected simplification

Initially d_r was always zero. That variant was fast: around 1.56 ms with
C=4. However, it preserves an exact alignment across fresh codes.

After seeing the bank, select 32 columns from each of two rows that map to
the same 32 stored regions. Fix those supports before sampling a fresh code.
Their sets of actual regions remain identical under every shared sigma.
Changing position shifts or choosing more region tables cannot remove this
invariant, because neither changes which stored region contains a column.

`composed_test.cpp` reproduces intersection 32 in all 32 tested fresh codes.
With fresh row shifts, the C=4 regression gives intersections from 1 to 8,
with mean 4.34375. Independent uniform 32-subsets of 256 regions have expected
intersection 4. This small regression checks removal of the exact invariant;
it is not a statistical validation of the corrected family.

The supports are arbitrary bank-adaptive coordinate sets, not demonstrated
BCH codewords. The invariant is therefore a permutation-family weakness,
not a demonstrated low-distance SPIN word or a PCG attack. Nevertheless,
the no-row-shift variant is not the recommended candidate.

## Matched performance

Ryzen 7950X, CPU 15, GCC 15.2. K=2^18, N=2^19, 128-bit elements,
BCH [256,128], T128S19. The table reports medians of nine process medians.
Each process measures 15 encodes and discards the first two. Fresh instance
and mask seeds advance on every encode. All benchmark processes run serially,
with order reversed on alternating passes.

| Flow | Fresh setup | Encode | Total | Overhead |
|---|---:|---:|---:|---:|
| Original-family, fixed precomputed code | amortized | 1.480379 ms | 1.480379 ms | baseline |
| C=1, fresh region and row shifts | 0.006442 ms | 1.612966 ms | 1.619398 ms | 9.39% |
| C=4, fresh region and row shifts | 0.006482 ms | 1.622824 ms | 1.629497 ms | 10.07% |

For C=1, paired overheads ranged from 8.26% to 11.00%, with median 9.25%.
The target is met by the median, not by every process measurement. C=4 is
borderline and does not meet the target using the ratio of medians.

Fresh totals include parameter allocation, mask generation, encoding, and
per-code destruction. Bank generation, scratch allocation/preparation, input
initialization, and checksumming are excluded. The bank and scratch persist
across fresh codes. Scratch receives the same owned-page huge-page treatment
as the fixed-code workspace; no machine-wide memory settings are changed.
One-time bank construction cost has not yet been reported for these variants.

C=1 stores 2 MiB of route tables; C=4 stores 8 MiB. The per-code parameter
and mask payload is 45 KiB. Value scratch is 8 MiB, plus an 8 KiB region
address buffer and the inner kernel's temporary state.

The raw confirmation directory is `results-bank-optimize-fastmasks` on the
benchmark host. These data remain outside source control. Earlier results
in `results-bank-optimize-rowshifts-confirm` used the scalar mask generator:
1.650 ms fresh versus 1.479 ms fixed, missing the target at 11.6% overhead.

## Screening completed and still required

Full encodes match a materialized-route reference for the same route and
mask seeds. The tests compare all K output elements. Routing tests enumerate
all N coordinates, check bijection and one-bit-per-row-per-region, and compare
scalar and SIMD addresses in both destination layouts. The alignment regression
and focused AVX2 ASan/UBSan tests passed. Native AVX-512 sanitizer checks
also passed for the fused row-shift copy and the exact mask generator.
All 23 registered bank tests pass in the portable build, including the
stronger row-map prototype. These focused
sanitizer runs do not instrument the entire existing encoder library.

Exploratory screens of the earlier input-rotation variant used eight fixed
banks and 131,072 draws per bank on 2,048 positions. Small banks showed clear
pair biases: worst XOR collision excess was around 0.007--0.008 for 16 entries.
Aggregating 256 or 512 independently sampled region tables brought the
measured excess near the uniform control's sampling noise, around 0.001.
These are marginal screens, not evidence for the final shift-only family.
In particular, averaging over stored-region selection does not establish
good behavior conditioned on a stored region or across multiple regions.

The subsequent [quality report](QUALITY.md) screens the actual C=1/C=4
shift-only family with fresh row shifts. Further work should cover:
fixed-bank pair distributions, four-point relations, bank-adaptive supports,
and cross-instance overlap tails. Include rare alignments, not just means.
Independent cyclic row shifts have only 256 possibilities per row, so a
small average overlap alone cannot rule out substantially enlarged tails.
No certificate is claimed for these heuristics.

## Reproduce

Portable correctness targets:

```sh
cmake -S spin -B out/bank-opt -DCMAKE_BUILD_TYPE=Release \
  -DSPIN_BUILD_EXPERIMENTS=ON -DSPIN_BUILD_TESTS=ON
cmake --build out/bank-opt --target spin_bank_optimize spin_bank_flows \
  spin_bank_test spin_bank_composed_test spin_bank_masks_test -j2
ctest --test-dir out/bank-opt -R '^spin_bank' --output-on-failure -j1
```

The winning build below is host-specific and requires AVX-512F, VL, DQ,
and VPOPCNTDQ. It is an experimental executable, not a portable installed API.
Use a Release `build/libspin.a` with the existing AVX-512 backend enabled.

```sh
g++ -O3 -DNDEBUG -std=c++20 -mavx2 -mavx512f -mavx512vl \
  -mavx512dq -mavx512vpopcntdq -mtune=znver4 \
  -DSPIN_COMPOSED_SHIFT512=1 -DSPIN_COMPOSED_SHIFT_UNROLL=1 \
  -DSPIN_COMPOSED_LOOKAHEAD=1 -DSPIN_WORKSPACE_ROUTING_OPT=1 \
  -DSPIN_BCH_AVX512=1 -Ispin/include \
  spin/experiments/permutation_bank/optimize.cpp build/libspin.a \
  -o build/spin_bank_fastmasks
SPIN_COMPARE_PASSES=9 \
SPIN_COMPARE_MODES=fixed,row-shift4-epoch,row-shift1-epoch \
bash spin/experiments/permutation_bank/compare_optimize.sh \
  COMPARISON_ROOT 15 spin_bank_fastmasks fastmasks
python3 spin/experiments/permutation_bank/summarize_optimize.py \
  COMPARISON_ROOT/results-bank-optimize-fastmasks
```

To exercise the vector mask generator and rejection fallback directly, compile
`masks_test.cpp` with the same ISA flags. Without those flags, the test exercises
the scalar fallback. The serial comparison script acquires all three shared
benchmark locks before running any timings.
