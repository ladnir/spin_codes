# Cached stores for small RS packet transposes

The K16 transpose was slower than the forward encoder despite using the same
code. Streaming stores were a substantial part of that difference. The transpose
scattered intermediate packets with non-temporal stores, then read that memory
in the outer stage. Small working sets benefit from retaining these writes in cache.

The production transpose now selects cached stores for K <= 262,144. Larger
inputs retain the original streaming-store path. This is an implementation
choice: the RS outer, packet permutation, GL20 updates, seeds, and output order
are unchanged. It does not require a new distance certificate.

## Public API comparison

Measured October 1, 2026, on Peach: Ryzen 9 7950X, CPU15, fixed 4.5 GHz, boost
disabled, GCC 15.2, Release, `SPIN_TUNE=znver4`. Both executables use
`Code::transpose_inplace_bytes` with 128-bit elements and precomputed setup.
Setup and allocation are excluded. Each process performs five warmups followed
by 501 timed calls on a reused buffer.

Each table entry is the median of four process medians. For each seed, 1 and 17,
the order is baseline/candidate/candidate/baseline. All benchmarks run serially
under the shared host locks, and every paired output checksum matches.

| K | Prior public implementation | Cached-store selection | Time reduction |
|---|---:|---:|---:|
| 2^16 | 0.212136 ms | 0.150736 ms | 28.94% |
| 2^18 | 0.824990 ms | 0.607554 ms | 26.36% |
| 2^20 | 3.311101 ms | 3.323329 ms | -0.37% |

K16 and K18 use normal allocation; K20 uses the existing huge-page preference.
The K20 result is effectively unchanged, not a speedup. Its store policy remains
unchanged. A separate control using cached stores at K20 took about 5.64 ms,
which is why the selection is size-dependent.

The baseline executable is the preserved SPIN 0.3 promotion build at
`/tmp/spin-rs-promotion-cSuY7w/build/spin_packet_bench`. The candidate uses the
committed `6799780c` package plus the cached transpose sources and boundary tests.
It excludes concurrent, uncommitted wide-forward work.
Author-side receipts are retained under `output/spin-rs-cached-20261001/` at the
repository root and `/tmp/spin-rs-cached-Gukkrs/` on Peach. Raw receipts are not
committed.

## Store-policy controls

`nn`, `cn`, `nc`, and `cc` independently select the route and outer store policies;
`n` means non-temporal and `c` means cached. The control translation units preserve
the generated instruction schedules and change only stores and their fences.
`phases=1` instruments both stages; use `phases=0` for whole-encoder comparisons.

Build the package and experiment from the same source revision:

```sh
cmake -S spin -B out/cached -DCMAKE_BUILD_TYPE=Release \
  -DSPIN_BUILD_BENCHMARKS=ON -DSPIN_TUNE=znver4
cmake --build out/cached -j3
cmake -S spin/experiments/packet_k16 -B out/store-controls \
  -DCMAKE_BUILD_TYPE=Release -Dspin_DIR="$PWD/out/cached"
cmake --build out/store-controls -j3
out/store-controls/spin_packet_k16 check
```

On the benchmark host, acquire all shared locks before running any measurements:

```sh
flock /tmp/prindal-addition-encoder-benchmark.lock \
flock /tmp/bare-spin-benchmark.lock \
flock /tmp/hypercat-benchmark.lock \
flock /tmp/hypercat-global-benchmark.lock \
taskset -c 15 out/store-controls/spin_packet_k16 cc 65536 1 501 0
```

Production kernels are generated by `spin/tools/import_rs_packet.py`. Separate
translation units preserve fixed hot-loop schedules; the size branch executes
once per encoding call. Cached stores require no streaming-store fence. Large
inputs retain both original fences and the 16-byte output-alignment fallback.

Validation passes all six Linux package tests and the full-library packet test
under ASan/UBSan with leak detection. The Windows/MSVC packet test also passes.
Added natural-length tests exercise K16
and the dispatch boundary at K = 261,888, 262,144, and 262,400. They compare the
portable oracle, separate-output and in-place calls, all permitted cache-line
offsets, output guards, and allocation-free encoding.

The follow-up route and scheduling controls
profiled the cached path and tested nineteen alternatives. None established a
further improvement. The present improvement does not change packet destinations.
