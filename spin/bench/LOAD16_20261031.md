# Sixteen-load schedule for paired-s15 forward encoding

October 31, 2026. The standalone library now includes the width-one load
schedule developed in Hypercat. A matched native comparison reduces encoding
from **3.007 to 2.144 ms per 16 MiB of input** on a 512 MiB workload.
The standalone SPIN benchmark measures **2.122 ms per 16 MiB** separately.

We call this normalization **time per million (TPM)**: milliseconds per
2^20 128-bit input elements. For wider records, it counts the same total
number of 128-bit payload elements. It counts input bytes, excluding the
rate-1/2 encoder's additional output bytes.

## Implementation

The change applies only to AVX-512 forward encoding with
`Parameters::PacketRsT64S15K16` and 128-bit records. Each 2 KiB outer group
is packed in two halves. The new schedule places sixteen 64-byte demand
loads before packing each half. An empty assembly statement consumes the
loaded ZMM registers, keeping all sixteen raw vectors live together before
the packing stores. This constrains the compiler's load schedule without
emitting a CPU instruction or fence.

The outer also prefetches the next group into L2 with `_MM_HINT_T1`.
The final group is handled separately to avoid prefetching beyond the input.
The parity arithmetic, symbol maps, inner encoder, scratch layout, seeded
code, and descriptors are unchanged. Widths two/four and transposed encoding
retain their preceding schedules. No allocation, additional buffer, or
memory-copy pass enters the encoding path.

Both [the generated source](../src/paired15/Paired15ForwardOuter.cpp) and
[its generator](../src/paired15/generate_forward_outer.py) contain the change.
The standalone library selects this schedule directly; it needs no Hypercat
adapter. The comparison baseline is frozen revision
`3ce07a64936c00e4a9853f1081ab676681bb3382`, before these load and prefetch changes.

## Matched native comparison

Three library builds use the same external native batch harness, Clang 21,
Release optimization, and `SPIN_TUNE=znver4`. The runs use one Peach Ryzen
9 7950X core, CPU15, fixed at 4.5 GHz with boost disabled. All benchmarks
run serially under the shared benchmark locks.

Input/output buffers use normal allocation and native scratch uses
`MemoryPolicy::Automatic`. Route and inner seeds are 1 and 2. Each encoding
uses streaming final-output stores and retains the complete output. Allocation,
setup, cache preparation, validation, and checksumming are outside timing.

Each table cell pools fourteen raw samples from two processes in reversed
case order and reports their median. It is not an average of process medians.
All times below are TPM in milliseconds.

| Library | W1, reused 16 MiB | W1, produced 512 MiB | W4, produced 512 MiB |
|---|---:|---:|---:|
| Frozen standalone SPIN | 2.040 | 3.007 | 3.364 |
| Frozen SPIN with the Hypercat adapter | 2.028 | 2.121 | 3.336 |
| Ported standalone SPIN | 2.007 | 2.144 | 3.372 |

Here W1 and W4 mean one and four 128-bit payload lanes per record.
The produced-input case rewrites input with streaming stores before each
timed batch; that rewrite is excluded. It models the encoder's input access,
not an entire prover execution.

The port reduces large-input W1 time by 28.7% against the frozen library.
Its median is 1.1% above the adapter's median in this run. The W4 measurements
provide a control for a kernel whose schedule was not changed.

The library's own `spin_forward_batch_bench` gives a separate confirmation:

| Standalone benchmark workload | Samples | TPM (ms) |
|---|---:|---:|
| W1, reused 16 MiB | 14 | 2.005 |
| W1, produced 512 MiB | 14 | 2.122 |

Those cells also use pooled raw-sample medians from two processes. Both
harnesses compare complete output bytes against a cached-store reference
before and after timing and check input preservation and buffer guards.
The native results remain above the 2.00 TPM large-input target.

## Full PCS check

The integration check uses the ported library with
`HYPERCAT_SPIN_INPUT_PREFETCH=0`, so Hypercat does not replace the outer.
It compares against the preceding adapter build on the same 512 MiB
SPIN–Brakedown workload. The new run measures fourteen samples per
configuration, split between two processes in reversed order.

| Haraka configuration | Encoding (ms) | TPM (ms) | Commitment (ms) | Opening (ms) | Commit + open (ms) |
|---|---:|---:|---:|---:|---:|
| Preceding Hypercat adapter | 67.566 | 2.111 | 152.042 | 92.911 | 244.936 |
| Ported SPIN, adapter disabled | 67.731 | 2.117 | 151.785 | 92.628 | 244.311 |

Each cell is a pooled sample median; phase medians need not sum to the
median total. The encoding difference is 0.24%. Both the ported encoding
median and its total-time median lie within the preceding adapter run's
sample ranges. These results support retaining the adapter's performance,
without establishing a further speedup from the port itself.

The ported BLAKE3 configuration measures 67.844 ms for encoding, or
2.120 TPM, and 350.064 ms for commitment plus opening. The full PCS results
therefore confirm that the standalone library supplies the optimization
without Hypercat's outer replacement.

## Validation and reproduction

The port passes `spin_paired15`, `spin_api`, and `spin_known_answers`.
The paired-s15 suite covers scalar/SIMD agreement, all forward widths,
alignment, guards, reused scratch, store policies, adjoints, frozen known
answers, and allocation-free encoding. The forward generator check,
frozen-circuit import check, and independent binary-adjoint algebra check pass.
The standalone benchmark's self-test also passes.

The Hypercat integration passes nine SPIN tests and four natural-layout PCS
tests. All twenty-eight full PCS samples verify, with zero Rust allocations
in the measured prover and verifier paths. Serialized proof fingerprints
match the preceding adapter build for both BLAKE3 and Haraka. The linked
static library contains the standalone `Paired15ForwardOuter.cpp.o` and no
adapter object.

All 126 matched-harness native batches have identical output checksums for
each width and input size. Together with the 28 standalone-benchmark samples,
this gives 154 checked native samples. The native port changes neither the
encoding map nor the PCS parameters.

The batch benchmark now accepts `g16`, `g512`, and 512-bit records, in
addition to its preceding shapes and widths. Its self-test checks all
fifteen width/shape combinations. The measured encoding loop is unchanged.

From the repository root on the measured Linux host:

```sh
cmake -S spin -B out/load16 -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER=clang++-21 -DSPIN_TUNE=znver4 \
  -DSPIN_BUILD_TESTS=ON -DSPIN_BUILD_BENCHMARKS=ON
cmake --build out/load16 --target spin_forward_batch_bench spin_paired15_test
out/load16/spin_forward_batch_bench --self-test
```

With the host frequency set as above, run these commands one at a time
under the shared benchmark locks:

```sh
taskset -c 15 out/load16/spin_forward_batch_bench paired15 128 g16 reused streaming 1 2 7 normal
taskset -c 15 out/load16/spin_forward_batch_bench paired15 128 g512 produced streaming 1 2 7 normal
```

Repeat in reverse order for the two-process comparison. Each process excludes
three warmup batches and measures seven batches. For `g16`, reported batch
milliseconds equal TPM. For `g512`, divide batch milliseconds by 32.
The buffer memory argument controls input/output; scratch remains Automatic.
