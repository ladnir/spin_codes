\section{Encoder Implementation and Performance}
\label{sec:implementation}

We measure the binary Turbo SPIN construction of
Section~\ref{sec:turbo-spin} through its public transposed-encoder
interface. The call maps $N=2K$ input records to $K$ output records;
each $128$-bit record carries $128$ parallel binary instances. It includes
the inner, packet routing, randomized column maps, RS outer, and store
fences. Table~\ref{tab:turbo-performance} gives the full online call time;
setup, allocation, and input filling are excluded.

The measurements use GCC~15.2 with Zen~4 tuning, one thread pinned to
CPU~15, and four setup seeds, each run twice in opposite seed order.
Each process has five warmups, followed by $2001$ timed calls at
$K\le2^{16}$ and $1001$, $301$, $101$, $31$, and $11$ at
$K=2^{18},\ldots,2^{26}$. The entries are medians of eight process
medians; every process median lies within $1\%$ of the entry. The
last column divides the time by the $2K$ input records. Input is not
restored between calls. $K\le2^{16}$ uses normal pages; the larger runs
request huge pages for data and scratch, which the operating system may
decline. Huge pages make no measurable difference at $K\le2^{18}$. All
runs are serial.

Up to $K=2^{18}$ the data fits in the $32$\,MiB last-level cache, and
both the inner route and the outer are compute-bound. From $K=2^{20}$
the cost per record rises by about $1.6$--$1.9\times$, because both
stages then stream from main memory. The route sends each region's
packets to every group, so a group's outer input is complete only after
the last region, and the two stages cannot be fused without changing the
code. A data-movement skeleton with the same access pattern bounds the
remaining headroom at $9$--$16\%$ for $K=2^{20},\ldots,2^{24}$.
Appendix~\ref{app:implementation} gives the implementation scope.

The measured applications instantiate the bit-level design with a fixed
BCH outer and the IMT inner. This BCH--IMT instantiation has
five finite half-rate certificates and optimized ordinary and transposed
encoders. Its $K=2^{20}$ transposed time is $9.289$\,ms, measured in a
separate campaign with a different memory policy. Appendix~\ref{app:implementation}
gives the BCH--IMT implementation and its comparison with other encoders.
We have no matched BAA or ordinary-encoding timing for Turbo SPIN, so we
report no corresponding speedup or direction comparison. The OT and PCS
application results in Section~\ref{sec:applications} use BCH--IMT.
