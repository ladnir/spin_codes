# Extending the four-bit sparse proof at a lower distance

At K=2^20 and N=2^21, every occupancy q=1,...,64 is now covered at
bad-output-weight cutoff 104857, corresponding to relative distance 5%.
This is a statement about those message classes, not a whole-code distance
certificate. Occupancies 65 through 2048 still need a matching dense bound.

The construction is unchanged: BCH[256,128], four adjacent independently
shuffled rows per group, independent regional packet and lane shuffles,
and two-update IMT(128,19). The maps, zero initial state, and absence of
flushing are the same as in [FIRST_CLOSURE.md](FIRST_CLOSURE.md). Setup is
sampled once and fixed for every message. An occupancy counts groups
containing at least one nonzero message row.

## Verified coverage

The existing theorem covers q=1,...,58 at cutoff 209715, so its upper
6.786362e-14 also applies at cutoff 104857. For each q=59,...,64, a new
complete CDF cover includes all support vectors in {38,...,256}^q, all
compatible outer messages, and all binomial(2048,q) group locations.

Every new cover uses output tilt 0.032, penalty 1, input-weight tilt 1,
and the base independent-row inner envelope. No optional full-feedback,
window-histogram, or density refinement was required. The bounds below
were replayed with 192-bit outward arithmetic; decimal uppers are rounded
up, and margins are rounded down.

| q | Splits | Leaves | Bad-message expectation upper | Margin, bits |
|---:|---:|---:|---:|---:|
| 59 | 1 | 60 | 5.257711e-319 | 1057.300627 |
| 60 | 1 | 61 | 1.398782e-252 | 836.641709 |
| 61 | 1 | 62 | 6.904732e-184 | 608.447184 |
| 62 | 1 | 63 | 5.411004e-113 | 372.941978 |
| 63 | 1 | 64 | 5.78982038e-40 | 130.343605 |
| 64 | 25 | 1078 | 1.040080e-104 | 345.423828 |

The larger margin at q=64 reflects a finer support cover, not an increase
in the estimated distance. The sum of the six decimal uppers is below
5.789821e-40, checked with exact rational arithmetic. Therefore

    U_(1..64) < 6.786362e-14 + 5.789821e-40.

The same sum applies to any smaller output cutoff. Markov's inequality
bounds the probability of any bad message in these classes by this sum.
There is no interpolation over unexamined occupancies.

## Reproduction

Run from the repository root. This command rebuilds the inner operators
without using cached values. It reproduces all six occupancies; the
25-split cap can produce stronger bounds than some table entries.

```sh
python -B research/workstreams/permutation_locality/independent_rows/verify.py --occupancies 59 60 61 62 63 64 --threshold 104857 --tilts .032 --penalties 1 --max-splits 25 --target-bits 52 --precision 192
```

The measured q=64 command used `--groups 64 --max-splits 25`. The other
five rows used the displayed occupancy list with `--max-splits 1` and a
local exact-dyadic operator memo. That run also attempted q=64, which
did not pass with only one split; the separate 25-split certificate
supplies its coverage. The memo was freshly generated by the q=64 run
and bound to the same sources, maps, precision, and construction.

A separate complete batch at cutoff 20971 verified q=59,...,64 with
at most one split and total upper below 1.571695e-28. The stronger 5%
results above supersede that batch for assembling a sparse handoff.

## Dense handoff

`assemble.py` accepts a complete dense atlas starting at q=65 only when
its output cutoff is at most 104857. It adds the explicit sparse upper
above. A dense atlas starting at q=59 can still use the original sparse
theorem at cutoffs up to 209715. Other handoffs are rejected.

The atlas driver allows an existing cover to be retargeted to a larger
minimum occupancy. This restricts its domain, so old empty cells remain
empty. Accepted bounds are nevertheless rechecked. Lowering the minimum
occupancy requires a new cover; it cannot reuse old emptiness decisions.

The next useful experiment is a dense cover starting at q=65, alongside
further sparse extension if the transition remains expensive. Neither
the optional handoff nor these sparse certificates alone close 1% or 5%
for the complete code.
