# What has to grow for a Turbo-like asymptotic family

## Root cause

The fixed RS8 constituent is not defective at the certified finite
lengths. The asymptotic problem is that one active local group always
has at most 64 active packets, while the number of possible groups
grows. The current random route gives each such group a positive,
length-independent chance of placing its packets in a bad time pattern.
The fixed 22-bit uniform-GL state gives each eligible pair a positive,
length-independent chance of returning to zero. The
[late-group](ONE_GROUP_OBSTRUCTION.md) and
[pair-return](PAIR_RETURN_OBSTRUCTION.md) events make these two statements
precise. Selecting a better fixed RS8 scalar profile removes the first
event, but not the second.

This is a feature of **fixed local support together with this route and
inner law**. It is not a theorem that every encoder using an RS8 kernel
must fail. A route or inner that deterministically rules out all short
bad paths could be another answer, but we do not have such a design or
proof. Growing the effective outer constituent is the cleanest route
supported by the existing asymptotic proof architecture.

## A concrete growing RS8 outer

Choose `b` as a multiple of 256 with `b >= c log2 N` for a constant `c`
to be certified; set `g=b/256` and divide the
message into `L` supergroups of `128g` bits (`N=bL`). In each supergroup:

1. Apply `g` copies of the deterministic, unrandomized eight-row
   GF(16) RS[8,4] circuit. This is a rate-half map to `b` bits.
2. Apply a uniform permutation of these `b` bits, an accumulator, a
   second independent uniform permutation, and a second accumulator.
   Sample this entire constituent once and reuse it in every
   supergroup, as in the proved growing-outer SPIN family.

The base circuit is already the RS8 part of the Turbo outer. The two
permute--accumulate layers work only inside each supergroup. Each
layer uses `O(b)` bit operations, so this outer uses
`O(N)` ordinary and transposed work. No timing claim is made: the two
new permutations and accumulator passes need a matched implementation
measurement.
Merely placing `g` RS8 blocks side by side would not help: a message
can activate only one of them, leaving a fixed-size local word. The
layers after the direct sum are what couple those blocks and can make
the effective local weight grow with `b`.

The exact binary weight polynomial of one 32-bit RS row is

\[
 R(z)=1+8z^6+348z^8+2024z^{10}+6784z^{12}
      +14352z^{14}+18502z^{16}+14352z^{18}
      +6784z^{20}+2024z^{22}+348z^{24}+8z^{26}+z^{32}.
\]

The base direct sum has polynomial `R(z)^(8g)`. This is an explicit
replacement for `G(z)^(b/24)` in the existing BAA outer-spectrum
formula. If `P_b(a,c)` is the exact uniform-permutation/accumulator
weight transition already used by the paper, the new shared outer has
expected enumerator

\[
 \bar A_b(w)=\sum_{a=1}^b\sum_{c=0}^b
 [z^a]R(z)^{8g}\,P_b(a,c)P_b(c,w).
\]

This identity is exact: the first permutation makes every fixed
base-output word of weight `a` uniform on that weight slice; the
second does the same after the first accumulator. The outer setup is
sampled once, so the realized spectrum must then be selected and
bounded before taking powers across supergroups. The old paper's
one-sample selection method applies once an expected-spectrum tail
and envelope are established.

The polynomial can be regenerated by
`python research/workstreams/turbo_spin_migration/rs8_base_spectrum.py`.
As a separate check on the current randomized RS8 base, its exact
expected number of nonzero binary words of weight at most 24 is
`1.0887234025e-5`; hence some fixed scalar profile has binary
minimum distance at least 25. This is a local existence statement,
not a scalable distance proof.

## First diagnostic and proof boundary

A numerical, non-certified optimization of the limiting BAA formula
replaced Golay's per-bit base log enumerator by `log R(z)/32`. At outer
relative weight 0.104, the resulting expected-spectrum exponent was
about `-0.0037021` nats per bit, versus `-0.0016928` for the Golay
base. At 0.11 it was `0.0059925` versus `0.0076424`. These comparisons
suggest that the deterministic RS row base is competitive in the
critical low-weight range. They do not bound all weights or establish a
theorem; the very low tails and numerical optimization need certified
coverage. The exploratory screen is
`python research/workstreams/turbo_spin_migration/screen_rs8_ba_exponent.py`.

There are two distinct next proof steps:

* **Outer bridge:** certify the BAA spectrum tail and concave envelope
  with `R(z)^(8g)`, then select one good shared outer. This can first be
  tested with the paper's bitwise route and IMT inner, whose transfer
  certificate already exists. The Golay certificate does not transfer
  automatically because its base polynomial changed.
* **Turbo bridge:** route the growing outer through four-bit packet
  regions and retain the width-64/s22 inner. Here the number of regions
  must grow as `b/4`; otherwise one supergroup supplies many packets to
  each fixed region and the current route analysis changes. Packet
  labels and the s22 fixed-occupation/dense transfers require fresh
  bounds. This is the family closest to the fast finite Turbo encoder.

The first step might yield a closely related scalable theorem while
keeping the RS8 base circuit. The second is the desired performance
and proof target. Neither is certified yet. The currently proved
11%/linear-work asymptotic family remains the Golay-BAA/IMT one. In
particular, the paper's constant `39/4` belongs to that certified
Golay/IMT instance; it is not a certified schedule for this RS8/s22
candidate.
