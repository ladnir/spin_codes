# Partial-row shortening: a probability rejection and exact route witnesses

Status: the state-4 and state-8 conclusions below are superseded by the stronger
deterministic [quiet-subcode cap](HD_BLOCKWISE_QUIET_SUBCODE.md). At packet width 64,
every identity-feedthrough setup has relative distance at most 12.5% for state 4
and 25% for state 8, for either outer [128,64] or outer [256,128]. The earlier
route-specific warnings and statements that outer-256/state-4 or state-8 remained
unexcluded are historical window-gate results, not current recommendations.
The derivations below are preserved as valid weaker statements. State 16 is not
rejected by the new 50% cap, but remains uncertified.

For the direct GRS[128,64] blockwise construction at K=2^20, state dimension
s=4 cannot provide 40% distance with a 40-bit setup margin. An exact finite
lower bound on actual distance failure is 0.0002115171265784. This rejection
holds for every realization of the causal linear inner coefficients.

State8 also has a concrete warning: bounded searches on three reproducible
routes each produce an actual bad-code subspace. The first route's frozen
witness has dimension at least 208 and output weight at most 838848. Its
validation uses exact row counts and the exit-rank bound, not a numerical
field-rank estimate. These witnesses do not supply a uniform failure-
probability lower bound. State16 remains open after the bounded tests below.

## Why paired windows strengthen the earlier gate

The missing feature in the earlier mean lower bound was connectivity.
Pair consecutive coordinate regions. Use a suffix window in the first
region of each pair and a prefix in the second. They touch across their
shared regional boundary, so only one zero-state exit is needed per pair.
There are 64 exits, not 127 or 128.

Use the packet-balanced lengths from HD_BLOCKWISE_GEOMETRY.md: 77 windows
of 6528 symbols and 51 of 6592 symbols. The total is 838848<0.4*2^21. Every
window is shorter than its region, so different pairs remain disconnected.
For independent uniform regional permutations, the shortened outer dimension
S has exactly the same mean as for the old window positions:

    E[S] = 344.6612109136314...,
    S = sum_rows (number of coordinates in the windows -64)_+.

MDS shortening gives this dimension without averaging over field values.
Setting the state to zero after each of the 64 connected windows costs at
most64s equations. If S>64s, injectivity gives a nonzero actual codeword
supported inside the windows. Because S<=838848/2=419424,

    Pr_route[distance <40%]
      >= (E[S]-256)/(419424-256)
      >0.0002115171265784                 when s=4.

The exact rational comparison exceeds 2^-40. Thus the setup margin cannot
exceed 12.207 bits. This is a probability lower bound, not a failed proof
upper bound. It needs no random coefficients from the inner.

State8 has 512 exit constraints, and state16 has 1024. This first-moment
lower bound is zero for both. That does not certify either state size.

## An exact partial-row witness for state8

The frozen route is generated by NumPy PCG64 with seed 0. For each of the
128 regions, call `rng.permutation(16384)` and store the result as int32.
This first array is the selection order, not the physical route. Reverse
the entire order in every even-indexed region and retain it in every
odd-indexed region, using zero-based indices, to obtain the physical route.
Thus the first W selected labels form a physical suffix in an even region
and a physical prefix in the following odd region.

The SHA256 of the int32 selection-order array is

    c090228e9769e5288d3216dac581ded5e48cf16d521c145468d25b246a94b58c

The validator checks this digest and reports a separate physical-route
digest. It stores all 128 packet lengths in `WITNESS_LENGTHS`. Their sum is
13107, and each length is between 82 and 120 packets. No region is full,
so the selected set has exactly 64 connected components and no free terminal
exit. The helper recounts all source-row occupancies from scratch.

The resulting shortening dimension is exactly 720. Its contributing rows
have the following hit histogram:

| Hits in selected windows | Number of source rows |
| ---: | ---: |
| 65 | 34 |
| 66 | 73 |
| 67 | 33 |
| 68 | 40 |
| 69 | 20 |
| 70 | 14 |
| 71 | 7 |
| 72 | 2 |
| 73 | 1 |
| 75 | 1 |

These 226 partially shortened rows contribute sum_i(t_i-64)=720. No row
has all 128 coordinates inside the selected windows. Hence this witness
does not arise from the complete-row event capped in HD_BLOCKWISE_GLOBAL.md.
We do not claim that this route avoids that event for every other window
family.

For state8, imposing the 64 zero-state exits gives at most 512 homogeneous
equations on this 720-dimensional source space. The resulting actual bad-code
subspace has dimension at least 208. Every nonzero member has nonzero output
supported in at most 838848 positions, strictly below 40% of N=2097152.
This holds for every linear inner setup of state dimension8 satisfying the
causal zero-input condition and injectivity. No GF65536 matrix needs to be
constructed: MDS shortening gives the source dimension exactly, and 512 is
a deterministic upper bound on the exit rank.

This is a reproducible construction instance, not a probability theorem
about PCG64 seeds or ideal uniform regional permutations. A low-probability
failure target permits some bad routes, so one exact route witness alone
does not disprove the desired 40-bit guarantee.

## Bounded search record and its limitations

The search starts from balanced packet lengths. A move transfers the same
number of packets from one region to another, preserving total output
weight and the paired-window topology. It calculates each move's exact
change in S, including rows appearing in both changed regions. The final
result is independently recounted; the frozen validator needs no search.

With allowed move sizes 1,2,4,8 and at most 256 moves, the first three fixed
seeds give:

| PCG64 seed | Initial S | Final S | State8 nullity lower |
| ---: | ---: | ---: | ---: |
| 0 | 364 | 720 | 208 |
| 1 | 364 | 751 | 239 |
| 2 | 320 | 695 | 183 |

These are not three mathematically independent uniform-route trials, and
no confidence interval is attached to them. They are reproducible evidence
that the state8 issue is not confined to a specially hand-constructed route.
The first row is frozen as the regression witness.

A separate bounded seed 0 search allowing packet moves through size 32 reaches
S=876. This is still below the 1024 exit capacity for state16. Failure to
find a state16 witness in that search proves neither good distance nor
absence of stronger window arrangements. No unbounded optimization or
native encoder experiment was used.

## Outer256 comparison

Pairing also sharpens the necessary geometry thresholds for GRS[256,128].
At width 64, there are 128 connected components. Exact balanced-window means
and the corresponding thresholds are:

| Outer and target | E[S], approximately | Minimum state not excluded by this paired mean gate |
| --- | ---: | ---: |
| [128,64], 40% | 344.6612 | 6 |
| [256,128], 40% | 10.49185 | 1 |
| [256,128], 45% | 1495.6694 | 12 |

The integer thresholds compare the exact lower bound against 2^-40, not
just against zero. Thus outer256 with state4 or8 is not excluded at 40%
by this argument, but both are rigorously excluded at 45%. The larger outer
reduces the shortened-row excess substantially at 40%; it is a genuine
geometry change, not merely a smaller implementation of the rejected
outer128/state4 candidate.

The helper accepts outer256 for a later bounded adaptive-window search.
No such search was used to label its 40% cases as unexcluded. The native
benchmark schedule is separate from these proof calculations.

## Proof consequence and next step

The prior cap for complete-row traps does not settle partial-row traps.
The state8 witness obtains 720 dimensions from many rows with small positive
excess, while containing no complete source row. A source-aware fractional
moment or rank bound must keep this shortened dimension and the connected
exit count. Replacing partial rows by full rows loses the mechanism.

At 40%, stop treating outer128/state4 as a candidate: the exact probability
bound rejects it. Outer128/state8 needs a substantially stronger probability
analysis or a geometry change before it can be considered proof-viable.
The concrete next comparisons are outer128/state16 and outer256/state4 or8,
with a bounded adaptive-window test for the latter and a full partial-row
existence bound for whichever geometry survives. None is certified here.

For complete-row traps in a new outer256 geometry, a useful next bound
would count the minimal containing span of each fixed row set directly.
Uniform regional permutations give exact finite order-statistic laws for
an arbitrary span and for an anchored prefix or suffix. Combining these
laws with the connected-window topology may avoid the earlier union over
every possible endpoint. Partial-row witnesses still require a broader
argument, because each row can use a different subset of coordinates.
