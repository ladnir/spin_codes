\section{Implementation and performance}
\label{sec:implementation}

We implement the selected BCH-256/RM2Sub $(128,19)$ construction from
Section~\ref{sec:finite-certificates}. The application evaluates the
transposed encoder on batches: $2K$ input blocks map to $K$ output blocks,
where each $128$-bit block carries $128$ parallel binary instances.
The pipeline applies the transposed inner, reverses the routing factors,
and applies the transposed BCH outer. No parity fanout is included.

\paragraph{Shared implementation and optimized kernels.}
The configurations share setup, routing, the paired BCH transpose, and
an RM2Sub template. Selected maps supply compile-time constants and checked
quadratic XOR circuits. The BCH circuit uses $3029$ scalar XOR operations
and evaluates two rows together with AVX2. Inner kernels use pruned SIMD
zeta stages, unrolled emission, and fixed nibble tables.
The online call has no allocation or type-erased callback dispatch;
configuration and layout dispatch occur once per encoding.

At $K=2^{20}$, packed $24$-bit routing indices and $2048$-row tiles reduce
routing overhead. The smaller measured instances use $256$-row tiles.
Grouped nibble tables improve the selected S19 kernel.
These are measured choices for the evaluation host, not processor-independent
optimality claims.

\paragraph{Correctness.}
Symbolic checks verify the generated BCH matrix and its transposed circuit,
the pruned zeta schedule, and the selected inner maps.
Runtime tests compare the complete optimized output with dense BCH
multiplication and a separately implemented scalar inner recurrence.
Tests cover routing layouts, tile sizes, setup compaction, multiple setups,
boundary impulses, zero inputs, and buffer validation.
The tested configurations agree under GCC and MSVC.

\paragraph{Measurement method.}
Measurements use one Ryzen 9 7950X thread on Linux, pinned to CPU~15, with
GCC~15.2.0. The release build uses \texttt{-O3 -DNDEBUG -march=znver4},
AVX2, and carry-less multiplication instructions.
Each reported time is the median of three independent serial run medians.
Each run performs three warmups and $101$ timed calls, reusing its buffers
and workspace. Setup, allocation, correctness checks, and output hashing
are outside the online interval. These are steady-state encoder latencies,
not cold-cache or full-application timings.

At $K=2^{20}$, the selected construction takes $6.6\%$ less time than the
$(64,20)$ reference. Its three run medians range from $11.105$ to $11.276$\,ms.
The measured setup takes $43.91$\,ms and includes construction of oracle

setup timing excludes this final deallocation and workspace construction.
The retained setup occupies $13.19$\,MiB, the workspace $40$\,MiB, and
the input/output buffers a separate $48$\,MiB.
No performance measurement is claimed at $K=2^{22}$ or $2^{24}$.

\subsection{Comparison with other transposed encoders}
\label{sec:transposed-comparison}

We compare SPIN with chosen-block BAA~\cite{cryptoeprint:2026/1903},
Expand--Convolute~\cite{RaghuramanRindalTanguy2023EC}, and binary
repeat--accumulate--accumulate (RAA)~\cite{blaze25}. Every call evaluates a binary
transposed encoder on $128$ parallel instances. No weighted extension-field
RAA or forward-encoder timing is included.

The BAA rows use the optimized Golay $[24,12,8]$ and RM$(2,5)$ kernels
from the companion implementation. Expand--Convolute uses the legacy
nonsystematic implementation with expander weight $w=33$ and memory $m=25$.
The implementation takes $24$ random taps plus one fixed tap and applies
one convolution pass. Its native interface modifies the input buffer and
writes the result to a preallocated output buffer. Our binary RAA adapter
uses two accumulator/permutation layers and a repetition transpose.
BAA and RAA use four-round Feistel permutations, with cycle walking for
non-power-of-two domains. SPIN retains its packed routing tables.
The measured times include each implementation's routing costs; they do
not establish a general ranking of the code families.

\paragraph{Common timing protocol.}
We rebuild all rows with one compiler and measure them on the same Ryzen
host and CPU as above. Each cell uses three serial processes, each with
three warmups and $101$ timed calls. Each process allocates and initializes
its buffers once, then repeatedly invokes the native encoder interface.
There is no input copy or reset between calls. Expand--Convolute operates
on the buffer left by the previous call; the other interfaces preserve
their input. Code setup, caller buffer allocation, and output hashing
are outside the interval; all work inside each encoder call is timed.
The BAA message lengths are $2^m-64$ for $m\in\{16,18,20\}$, allowing
both constituents to tile the same input. All other rows use $K=2^m$.
RAA processes $3K$ or $4K$ input blocks, versus $2K$ for the rate-$1/2$ rows.

At the largest measured length, SPIN takes $11.104$\,ms.
Chosen Golay and RM BAA take $2.16$ and $2.49$ times as long,
respectively. The conservative EC profile takes $181.825$\,ms.
The repetition-$3$ permutation domain requires cycle walking; the
repetition-$4$ domain does not. These measurements do not imply that
lower-rate RAA is intrinsically faster.

For context, the companion BAA evaluation reports $22.810$\,ms for Golay
and $24.278$\,ms for RM at the same code parameters, using an Intel
i9-14900HX and MSVC. Table~\ref{tab:transposed-comparison} instead uses
our same-host rerun and does not combine cross-machine timings.

\paragraph{Distance context.}
At the largest lengths, SPIN's certified margin is $50.448$ bits at
relative distance $0.10$. The companion BAA evaluation reports full
first-moment margins of $46.386$ and $47.093$ bits for Golay and RM,
respectively, at the same distance target and their measured length.
For EC, we use the conservative profile reported in the earlier
comparison~\cite{KolesnikovEtAl2026BA}: relative distance $0.05$ with
a $20$-bit margin at $K=2^{20}$. These bounds concern each construction's
stated random ensemble. For repetition-$4$ RAA, we report Blaze's
published no-test reference bound at $K=2^{22}$ separately from our
smaller timing sizes. Its relative distance is $0.19$, with an approximately
$13$-bit margin; setup testing can improve this margin as noted in the table.
We do not transfer this bound to $K=2^{20}$ or to repetition-$3$ RAA,
nor extrapolate the BAA or EC margins to smaller lengths.
