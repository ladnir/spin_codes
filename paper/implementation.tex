\section{Implementation and performance}
\label{sec:implementation}

We implement the selected BCH-256/RM2Sub $(128,19)$ construction from
Section~\ref{sec:finite-certificates}. The application evaluates the
transposed encoder on batches: $2K$ input blocks map to $K$ output blocks,
where each $128$-bit block carries $128$ parallel binary instances.
The pipeline applies the transposed inner, reverses the routing factors,
and applies the transposed BCH outer. No parity fanout is included.

\paragraph{Shared implementation and optimized kernels.}
The configurations share setup, routing, the paired BCH transpose, and
an RM2Sub template. Selected maps supply compile-time constants and checked
quadratic XOR circuits. The BCH circuit uses $3029$ scalar XOR operations
and evaluates two rows together with AVX2. Inner kernels use pruned SIMD
zeta stages, unrolled emission, and fixed nibble tables.
The online call has no allocation or type-erased callback dispatch;
configuration and layout dispatch occur once per encoding.

At $K=2^{20}$, packed $24$-bit routing indices and $2048$-row tiles reduce
routing overhead. The smaller measured instances use $256$-row tiles.
Grouped nibble tables improve the selected S19 kernel.
These are measured choices for the evaluation host, not processor-independent
optimality claims.

\paragraph{Correctness.}
Symbolic checks verify the generated BCH matrix and its transposed circuit,
the pruned zeta schedule, and the selected inner maps.
Runtime tests compare the complete optimized output with dense BCH
multiplication and a separately implemented scalar inner recurrence.
Tests cover routing layouts, tile sizes, setup compaction, multiple setups,
boundary impulses, zero inputs, and buffer validation.
The tested configurations agree under GCC and MSVC.

\paragraph{Measurement method.}
Measurements use one Ryzen 9 7950X thread on Linux, pinned to CPU~15, with
GCC~15.2.0. The release build uses \texttt{-O3 -DNDEBUG -march=znver4},
AVX2, and carry-less multiplication instructions.
Each reported time is the median of three independent serial run medians.
Each run performs three warmups and $101$ timed calls, reusing its buffers
and workspace. Setup, allocation, correctness checks, and output hashing
are outside the online interval. These are steady-state encoder latencies,
not cold-cache or full-application timings.

At $K=2^{20}$, the selected construction takes $6.6\%$ less time than the
$(64,20)$ reference. Its three run medians range from $11.105$ to $11.276$\,ms.
The measured setup takes $43.91$\,ms and includes construction of oracle
and alternative routing data. Those data are discarded before online timing;
setup timing excludes this final deallocation and workspace construction.
The retained setup occupies $13.19$\,MiB, the workspace $40$\,MiB, and
the input/output buffers a separate $48$\,MiB.
No performance measurement is claimed at $K=2^{22}$ or $2^{24}$.
